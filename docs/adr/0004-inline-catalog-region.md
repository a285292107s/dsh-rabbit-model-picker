# 0004. 模型目录改为账本行内的展开区，不再用右侧抽屉

## 状态

`accepted`（取代 Q27 的「右侧抽屉」形态；Q26 的「提供商级不弹层」继续有效）

## 背景

「模型配置」页的提供商行里，模型格（`N 个模型` / `默认`）原先打开一个 **右侧抽屉**
（`ModelDrawer.tsx` / `drawerStyles.ts`：`position: fixed`、自带 scrim、`role=dialog` +
`aria-modal`、Tab 陷阱、document 捕获 Esc）。设计时的理由是「保留页面上下文」（Q27）。

真机复核后，这个理由不成立：

- 宿主设置弹窗给这一页的内容列只有 **560 / 484 / 106px**（1920 / 768 / 390 视口），
  抽屉固定 **460px**：覆盖内容列 **82% / 95% / 全屏**，只剩约 100px。
- 抽屉贴视口右缘、全高，而设置弹窗居中、带圆角；宽屏（1587）下抽屉整个落在弹窗**外面**，
  两者之间还有一条缝——视觉上它是弹窗的兄弟层，不是子层。
- 为了让它工作，抽屉必须模拟第二个 modal：两个 scrim、两个 `aria-modal`（套叠）、
  自己的焦点陷阱、document 捕获 Esc（不捕获就会一次 Esc 连设置一起关）。
- 抽屉只能问 `@media`（fixed 的宽度来自视口），而整页其余部分问 `@container`——同一页两套响应式语法。
- 抽屉卸载即丢草稿；关闭后焦点没有归处（落回 `<body>`）。

宿主自己的官方 **模型** 页把 API 密钥、模型 ID/显示名、添加模型、获取可用模型全部摊在
同一个内容列里，没有第二层弹层。也就是说「把模型目录摊在内容列里」是宿主的既有做法。

## 决策

模型目录是 **provider 行的行内展开区**（`ModelCatalog.tsx` / `catalogStyles.ts`），不是弹层：

- 模型格是 disclosure：`aria-expanded` + `aria-controls`，无 `aria-haspopup`。
- 展开区是 `.dmc-row` 的 grid 子元素（`grid-column: 2 / -1`），占满设置内容列、随页面滚动；
  无 `position: fixed`、无 scrim、无阴影/圆角/入场动画、无 `role=dialog`/`aria-modal`、无焦点陷阱。
- 头部只陈述目录自己（`模型目录` + 自定义/默认），不重复提供商身份（上面那一行账本已说了）。
- 花名册、井、发现三步、保存/恢复默认原样保留。
- **草稿守卫**：收起或切换到另一个提供商前，若有未保存修改，先显示
  「有未保存的模型修改。继续编辑 / 放弃修改」；草稿从不静默丢失。
- **Esc 一次一层**（document capture）：设置井的 key 字段 → 模型井（焦点回 `编辑`）→
  发现清单 → 未保存问题 → 目录区收起 → 宿主设置面板。
- 收起后焦点回模型格；开目录不抢焦点，Tab 自然进入展开区。

## 后果

**正面**

- 设置弹窗重新成为唯一一层 modal：屏幕上只有一个 scrim、一个 `aria-modal`。
- 内容列从 460/560 的 82% 覆盖率变成 100% 可用；窄分支回到页面统一的 `@container`。
- Esc、焦点、滚动都退化为普通页面语义；关闭后焦点有归处。
- 与宿主官方页、与页面自己的「行 + 井」语法一致：整个 tab 只有一种编辑形态。
- 可逆：删掉目录区渲染即回到只读账本，不涉及宿主外壳。

**负面**

- 页面变长：一个 7 模型的目录展开约 +600px，需要页面滚动。
- 草稿守卫是本轮新增的交互面（三句文案 + 两个动作），不是抽屉时代的既有行为。
- 不能同屏对照另一个提供商的目录（一次只开一个），切提供商是一次点击。

**中性**

- 展开区与设置井可以同时打开（开井不关目录，避免丢稿；开目录会关井）；
  同一条账本行因此可能很长，这是有意的取舍。
- 旧的抽屉截图（`model-config-37/38`）与旧的抽屉预览脚本退役；新形态以真机截图
  `model-config-39-catalog-inline-dark.png` 与 `shots/page-preview-*.png` 为证。
  （`shots/` 与预览脚本已于 2026-10-18 整体删除；这里保留当时的证据指向。）

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| 页内子页（provider 列表 → provider 详情页） | 只去掉弹层、保留一次导航跳转；目录与发现需要独立一屏，但和「行 + 井」的账本语言仍隔一层。作为行内过长时的备选保留 |
| 抽屉贴回弹窗内（absolute + 去 scrim） | 420/560 仍盖 75%，仍是第二个 modal 的语义；返工不值得 |
| 把设置外壳也改成抽屉/整页 | 外壳是宿主的，插件只拥有 section；即使能改，也只是把一种两层换成另一种两层 |
| 模型发现单独开弹窗 | 那正是本轮要消灭的第二层 |
