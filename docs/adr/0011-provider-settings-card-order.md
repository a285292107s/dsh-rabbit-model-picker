# ADR 0011 — 供应商设置卡的编排：连接 → 端点 → 身份 → 重试 → 危险区

- 状态：已采纳（2026-10-19）
- 相关：`src/client/ModelConfigPage.tsx` 的 `ProviderRow`、`src/client/modelConfigStyles.ts`、`src/client/RetryEditor.tsx`、`src/client/modelConfigCopy.ts`
- 视觉依据：ADR [0008](0008-host-native-language.md)（宿主原生）与 `CONTEXT.md`「宿主字阶」「四档动作」

## 背景

设置井同时承担四件事：修连接、改端点、改身份、调重试，再加一个删除。原来的顺序是
凭据 → 显示名称 → API 地址 / 协议 → 重试 → 删除，并把唯一的填充主按钮放在重试块。
站在用户视角，这有三个问题：

1. **主路径被打断**：用户打开设置最常见的目的，是换 key 或改地址；显示名称是全宽的次级字段，
   却夹在凭据与端点之间。
2. **视觉主次倒置**：重试是低频的高级设置，但它的「保存」是卡里唯一的黑底按钮；连接与端点字段
   即时保存，没有对应的动作，用户容易把重试的「保存」当成整张卡的保存。
3. **动作语义不清**：清除密钥是中性文字动作，但它会移除已保存的认证；行头的两个门在打开后
   没有视觉状态。
4. **地址与协议挤在两列网格里**：地址要逐字符读（主机、路径、结尾的 `/v1`），协议只是一个短
   枚举；各占一半宽度时，`https://dashscope.aliyuncs.com/compatible-mode/v1` 这类地址在
   输入框里只剩前半截，恰好藏起要核对的结尾。协议标签最长 23 个字符，并不需要同样宽的格子。

## 决定

1. **字段顺序**改为：凭据 → API 地址 → API 协议 → 显示名称 → 自动重试 → 危险区。
   连接与端点成为连续的主路径；显示名称退到端点之后，作为次级身份字段。
   每行一个字段：地址独占整行；协议另起一行，选择器按内容宽度（上限整行），后面跟
   「恢复跟随默认」。不再把两个需求不对称的字段塞进同一行。
2. 在字段网格末尾加一句 12px 的「以上设置即改即存。」；重试的提交按钮改名为
   「保存重试设置」，并从主按钮降为描边按钮。卡片内不再有黑底主按钮。
3. 「清除密钥」改用危险档（红字、hover 红底）；「移除提供商」保持危险档与行内两步确认。
4. 行头的「模型设置」「提供商设置」在对应区域打开时带 `data-active`，用宿主 hover 底色显示
   当前状态；不改变文案与宽度。
5. 不新增分区标题、不收起重试块：既有契约要求重试编辑器打开井即可见，重试块自带分隔线与
   标题，足以说明作用域。

## 取舍

- **地址整行、协议另起一行**：多出约一行（66px）的高度，换地址可见约 60 个字符；并排时
  两侧都看不全，是最差的折中。
- **显示名称更靠后**：改名不是高频路径；行头始终显示当前名称，改名仍只需打开设置井。
- **重试保存不再显眼**：它仍有独立的描边按钮与「保存重试设置」文案；把这颗主按钮让给内容，
  避免与即改即存的字段抢语义。
- **清除密钥仍然一步执行**：它只清掉一个 ref，和删除提供商的影响面不同；两步确认留给删除。

## 后果

- `ProviderRow` 的字段顺序、行头状态、清除密钥档位与重试按钮档位变化；`data-active` 样式加入
  `modelConfigStyles.ts`。设置井的 `.dmc-fields` 收成单列，协议选择器新增 `.dmc-protocol-select`
  按内容宽度；两列网格只保留给自定义提供商表单的 `.dmc-custom-fields`。
- 新增文案键 `config.well.instant`、`config.retryPolicy.apply`；删除未再使用的 `config.delete.title`；
  `config.delete.confirm` 收敛为「确认删除 / Confirm delete」（说明文字已经点明 provider）。
- 静态对照 fixture 在 `.taste-skill/v5/`（已被 `.gitignore` 忽略）；宽 / 窄、亮 / 暗状态截图在
  `shots/`，不是真机验收。
