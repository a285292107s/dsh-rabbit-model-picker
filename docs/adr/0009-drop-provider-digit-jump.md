# ADR 0009 — 删除数字键跳提供商

- 状态：已采纳（2026-10-19）
- 取代：ADR 0008「取舍」里「数字键跳行仍然可用」那一句
- 相关：`src/client/ProviderRail.tsx`、`src/client/Picker.tsx` 的卡底、`src/client/dictionary.ts`、`src/client/styles.ts`

## 背景

ADR 0008 删掉了提供商栏的 `01`–`09` 序号，理由是「画了就是装饰冒充快捷键」，同时保留了数字键跳转本身。
之后卡底加了一行常驻提示「数字键跳提供商」（`card.railKeys`），让这个没有序号的快捷键保持可发现。

复核这个快捷键的实际能力后，它没有撑起一行常驻提示：

1. **只在栏内生效。** 处理器挂在提供商栏的 `onKeyDown` 上。焦点在搜索框时，数字是输入过滤词（这才符合直觉）；
   焦点在模型列表时数字没有任何反应。提示读起来却像是全局快捷键。
2. **编号与可用序号不对齐。** 数字取 `options` 下标，失败行也在里面；命中失败行直接返回，不顺延到下一个可用行。
3. **只覆盖前 9 个。** 提供商超过 9 个时，其余的根本跳不到。
4. **同一条路径已有完整等价物。** 栏内 `ArrowUp` / `ArrowDown` / `Home` / `End` 就是同一件事，`Enter` 选中。

也就是说，它省下的只是「栏内跨几个位置」的那几下按键，代价是一个容易被误读为全局快捷键的常驻提示。

## 决定

提示与处理器一起删除：卡底不再出现「数字键跳提供商」，栏内不再响应 `1`–`9`。提供商导航只剩方向键、
`Home` / `End` 与 `Enter`。

## 取舍

- **放弃「多提供商时的一键直达」**：栏本身是 roving tabindex 的 listbox，方向键就是它的标准导航；
  数字键是标准 listbox 之外多出来的一条捷径，与宿主自己的列表不是同一套语法。
- **保留卡底的两个陈述**：左边「显示 N / M 个模型」，右边「N 个提供商」（多提供商时才出现）。

## 后果

- 卡底少一个文案键（`card.railKeys`，zh/en 同键同序删除），少一条 `.dmp-card-foot-keys` 样式。
- 提供商栏的键盘契约收敛到 listbox 的通用键位；以后若要再加数字直达，需要先解决「失败行占号」
  与「超过 9 个提供商」这两件事，而不是补一行提示。
