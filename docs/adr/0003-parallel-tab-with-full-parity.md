# 0003. 新增平行 tab，不遮蔽官方「模型」页，但做到功能对等

## 状态

`accepted`（supersedes [0001](./0001-parallel-provider-config-tab.md) 与 [0002](./0002-phased-parity-then-shadow-models.md)）

## 背景

用户的目标经历了一次收敛，两次改口都留有记录：

- **ADR 0001**：新增平行 tab，官方页作**全功能兜底**，本插件**只做提供商级主干**、不复刻官方语义。
- **ADR 0002**：改为**分阶段**——先并存对照，功能对等后再**遮蔽** `id: 'models'`。
- **2026-10-16**：用户再改为「**一次性做完，不拆阶段**」，随后在两处关键分岔上选定：
  落地形态 = **仍以新 id 并存、不遮蔽**；语言 = **补英文、与官方页对等**。

三者合起来的唯一自洽解是：**界面上并存，能力上对等**。
遮蔽被放弃（官方页永远在），但 ADR 0001 里「只做主干、不复刻语义」的省成本前提也不再成立——
因为用户要的是「功能做全」。

## 决策

本插件以**新 id**（「模型配置」）注册 `settings.section`，与官方 `id: 'models'` **并存**；
**不遮蔽**官方页、不占用 `models` 这个 cell。
同时，本页的功能范围**与官方模型页对等**——把官方页的全部能力实现一遍
（逐条清单见 `docs/models-page-parity-checklist.md`），并**同时提供中文与英文**两套文案。

遮蔽不再作为未来方向：`settings.section` 的 `models` cell 永远由官方包持有。

## 后果

**正面**

- 设置里永远有一条回到官方实现的退路：本页哪里做得不对，用户点另一个 tab 即可绕开。
- **没有迁移风险**——官方页从未消失，因此不存在「用户没同意就换了界面」。
- 与官方页共用同一份设置文档、同一套写入通道，两边状态天然一致。
- 保留独立 tab 形态既有好处：新 id 注册、卸载即还原、不抢官方 cell。

**负面**

- **付两份维护成本**：同一个模型设置界面在安装里存在两份实现，官方包升级时本页不会自动跟上。
  这是「并存 + 对等」组合的固有代价，也是本决策与 ADR 0001 最大的分野——0001 正是用「不做对等」换掉了它。
- **两份界面会状态一致但操作不同**：同一份设置文档，用户在两个 tab 里看到的排版与步骤数不同。
  必须有文档指明哪个是本插件的入口，否则用户会随机选一个，并以为差别是 bug。
- 全量对等意味着本页要自己承担并发冲突、只读态、代际控制、推送失效重取等语义；
  漏掉任何一项都会在多页面同时操作时表现为「改了没反应」。
- **双语**把一个原本只需中文的文案面翻倍。

**中性**

- 新增 tab 在导航里回落齿轮图标（shell 的 id→图标 switch 不认识新 id）；官方页保留自己的图标。
- ADR 0001 的「用新 id 并存」被本文继承，0001 与 0002 同时被本文取代。

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| ADR 0002：分阶段，最终遮蔽 `models` | 用户改为「一次性做完，不拆阶段」，且在落地形态上选了「不遮蔽」 |
| 遮蔽 `models` 但保留一个可切回官方页的对照开关 | 用户未选；且「切回官方实现」的开关本身需要设计出口，成本高于直接并存 |
| 功能做全但只出中文 | 与 Q24 相反；虽因官方页仍在而不至于不可用，但一个对等实现缺一半界面 |
