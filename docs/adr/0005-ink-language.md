# ADR 0005：视觉语言定为「墨色」（单色 + 宿主蓝 + 局部墨晕）

- 状态：已接受（Accepted）
- 日期：2026-10-17
- 决策者：Lead（用户在同一天的两次直接指令：先要求整体焕新并以《明日方舟：终末地》为参考；
  随后明确修正——「摒弃 HUD 风格，我们不是游戏 HUD」「软黄色背景和 DSH 默认色差异过大，
  应以黑、灰、水墨质感为背景色」，并选定：单色 + 宿主蓝、移除 HUD 元素保留线与序号、局部墨晕 + 细微噪点）
- 影响范围：本插件拥有的全部表面（座位行 / 模型卡 / 参数面板 / 模型配置页 / 模型目录区 / 重试编辑器 / 徽章图标），
  三张样式表、令牌层、内嵌字体、质量门与交付文档
- 相关：`docs/ink-design-language.md`（现行规范）、`DESIGN.md` §5.38（实现记录）、ADR 0003

## 背景

旧语言（§5.32–§5.37 的 quiet-instrument / 路由账本）被用户判定「过于呆板乏味」。第一版重制
采用游戏《终末地》的 HUD 语汇：近黑底、信号黄、英文大写字段码、大号显示数字、切角与扫光。
它在静态预览里成立，但用户随即否决了它，理由有两层：

1. **体裁错位**：这是 DSH 设置/输入条里的软件界面，不是游戏 HUD。字段码、括号计数、大号仪表数字、
   切角与扫光借来的是一套不属于这个场景的语汇。
2. **调色错位**：暖纸底与柠檬黄和 DSH 默认的中性灰/蓝相差太大，放在宿主界面里读起来是「另一个产品」。

用户给出的替代方向很明确：**黑、灰的墨色；水墨质感落在背景；强调色用单色 + 宿主蓝；
HUD 元素移除，只保留线与序号。**

## 决定

采用**墨色语言**，规范落盘为 `docs/ink-design-language.md`：

1. **中性纸/墨 + 宿主色**。令牌层 `--zmd-*` 只定义中性面板/沉底/悬停/细线/三级墨与墨晕两端；
   强调色与错误色**直接指向宿主令牌**（`--dsw-alias-state-business-primary` /
   `--dsw-alias-state-error-primary`），不再引入第二套品牌色。黄色整套删除。
2. **单色优先**。所有层级靠墨的深浅、字号、1px 细线与留白；宿主蓝只回答「你在这里 / 点这里」
   （当前会话 2px 左条、选中勾、焦点环、展开动作 hover 下划线），且**蓝永不作文字**
   （亮色下 3.91:1，不达 AA；蓝底上的勾用 `--zmd-on-accent`）。
3. **水墨落在材质**。`.zmd-wash`（低对比径向墨晕，亮暗两套端点）+ `.zmd-grain`
   （120px 中灰分形噪点、SVG 自带 alpha 约 5%、`pointer-events:none`）只出现在有边界的表面
   （模型卡、参数面板、模型目录区）；不铺全屏、不压在文字上。文字对比度对墨晕两端分别测量。
4. **HUD 语汇全部退役**：英文字段码与 `FIELD_CODES`、大号显示数字、括号计数、14px 切角、
   顶部扫光、信号黄条、`■` 前缀全部删除；保留 1px 细线、两位数序号、字阶层级、双栏/井/花名册结构。
5. **交互契约零改变**：座位 shadowing、单层模型卡、设置唯一 modal、行内展开、
   键盘链/ARIA/宽度预算全部保留。
6. **内嵌字体保留**：上一轮用户明确要求内嵌一个开源窄体拉丁；Archivo Variable（OFL）子集
   46.7KB woff2 继续随包发布，但只用于常规字重与字距，不再做 `wdth` 125 的仪表盘显示字。
7. **质量门逐条修订**：上一版为 HUD 立的门（信号黄、切角、字段码、大序号、点阵）整套退役，
   换成墨色规则：令牌来源、1px 三类预算中的「2px 强调条只许宿主蓝」、墨晕/纸纹的唯一样式面、
   蓝不得作文字/蓝底必须 on-accent、对比度对墨晕两端测量、字体与构建新鲜度不变。

## 后果

- 正面：与 DSH 默认调色一致（中性灰、宿主蓝），不会在宿主界面里「像另一个产品」；界面有材质与
  层次但不再有游戏 HUD 的噪声；所有画字仍被门逐条量过；字体离线、可审计。
- 代价：**可借的装饰语汇更少**——第一版用字段码/大数字/切角制造的「结构感」现在只能靠细线、
  序号、字阶与留白；需要更克制地使用宿主蓝，否则会回到「到处都蓝」。卡片行高仍比旧版大
  （38px），可见行数减少；106px 档仍是「有序降级」。
- 维护面：`designSystem.ts` 令牌层与两个材质原语、`fontAsset.ts` 生成物、对比度门的
  `--zmd-*` 解析与白名单、纸纹/墨晕的允许面断言。
- 被拒绝的替代方案：① 保留 HUD（用户明确否掉）；② 保留一档黄色但压暗（仍是黄调，用户要单色）；
  ③ 完全单色无强调（用户选了「单色 + 宿主蓝」）；④ 强水墨晕染（会离软件界面更远，用户选「局部墨晕 + 细微噪点」）。
