# ADR 0012 — 参数面板改「读数优先」：值、来源、控件三行一组

- 状态：已采纳（2026-10-19）
- 相关：`src/client/SettingsMenu.tsx`、`src/client/panelCopy.ts`、`src/client/styles.ts`、`src/client/dictionary.ts`、`CONTEXT.md` 的视觉语法一节

## 背景

参数面板在 300px 宽的静态 fixture 里量到 **668px 高**，而它自己的上限是 460px——打开就要滚动（真实宿主的全局边距重置可能让绝对值略小，但超过 460px 这一点不变）。更慢的是读：

1. 三个参数的当前值分别藏在三种控件里：两个开关的 on/off、输入框（未声明时只有灰色占位）、
   一组列表里被高亮的那一行。要看「现在是什么」，得先在控件里反推。
2. 「这个值是我改的、适配器给的，还是目录公布的」写在每段下面的条件句里，最多三句，
   每句 4–30 字，300px 下各占 1–2 行。
3. 「写入位置」原始路径（`llm-pi-ai · settings/providers/...#models.0`）和一段 90 字的说明
   占掉约四分之一面板，且对每个模型说的是同一件事。
4. 页脚「恢复默认」在没有可恢复的改动时仍是灰按钮，占着位置、不说明为什么不能点。

编辑动作本身是清楚的；不清楚的是**先读**。面板一次打开要回答的是「这个模型现在是什么参数、
哪些是我改的」，然后才是「改哪一个」。

## 决定

**读数优先：每段先给一行读数，再给就地控件。** 面板从「四个区块的表单」变成「三行参数 + 一个页脚」。

| # | 规则 | 为什么 |
|---|---|---|
| 1 | 页首是身份：模型名 16/24 + 提供商 12/18；不再放「已自定义」总标签 | 面板会脱离触发器的上下文独立出现；提供商名比一个重复的总标签更能定位「这是哪个模型」 |
| 2 | 每段两行：读数行（标签 12/500、来源标签 12/400 右对齐占 88px，**值只在控件无法显示时出现**）+ 控件行。输入类型：两个开关就是值（只有额外模态才写完整集合）；上下文：已声明时选中的档位或自定义输入框就是值，继承时读数写生效值，未声明时写「未设置」；推理等级：选中的胶囊就是值 | 值不在控件之外重复；来源固定在右端；唯一需要读数补位的是「输入框为空」的继承态 |
| 3 | 来源标签只有五种：已自定义 / 内置目录 / 适配器默认 / 未声明 / 仅本会话 | 把原来的条件句压成一个名词；「已自定义」同时回答了「恢复默认为什么可用」 |
| 4 | 输入类型：两个开关并排；推理等级：单行胶囊列表（选中 = `--zmd-hover` 底 + 500）；上下文窗口：四个常用档位 **128K / 256K / 512K / 1M** + **自定义**，选中档位时输入框不出现，选「自定义」时输入框出现并保留 `formatContext` 的精确 token | 三段控件都在一行内；档位让「当前 + 可选」一起出现；值和控件不重复占两行 |
| 5 | 上下文输入框的占位文案分三态：已声明「留空恢复适配器默认」、继承「沿用适配器值」、无值「例如 128K」 | 说明句从段下移到它真正要指导的控件里；输入框为空时也知道回车/失焦会发生什么 |
| 6 | 非法数值的反馈留在输入框正下方（12/18 危险色），不再走顶部提示 | 错误和它对应的字段在同一视线内 |
| 7 | 页脚只留范围句；原始写入路径放进范围句的 `title`；「恢复默认」只在「已自定义且可写」时出现 | 可见路径是稀有需求；不可用的动作不占位、也不制造灰字的低对比 |
| 8 | 只读部署里推理等级仍可点（它走会话选择，不走设置服务） | 与面板的只读提示一致；原实现已如此，这次在布局里保持 |
| 9 | 档位按输入框的十进制 K/M 语义：128K=128000、256K=256000、512K=512000、1M=1000000；二进制容量（如 262144）不硬凑到 256K，落到自定义档 | 与 `parseContext` 同一把尺子，避免「点 256K 实际写 262144」的静默改写；继承值不预选档位 |

纯逻辑在 `panelCopy.ts`：`inputSourceOf` / `contextFactOf` 只回答「值从哪来」，
`FACT_SOURCE_KEYS` 把来源映射到文案键；组件只负责排版与写入。文案中英同键同序。

## DOM 关联（实测，2026-10-19）

在真实 GUI 里读到的结构与 primitive 行为（DSH 0.2.1-rc.2 / primitives 0.2.1-rc.2）：

- **Input**：渲染成裸 `<input class="_input_*">`，**不转发 `className`**。旧样式 `.dmp-settings-input`
  及其 `input` 后代规则实际是死代码，宽度一直是宿主 input 的内容宽。宽度改由结构行拥有：
  `.dmp-settings-field`（flex）包住 input，`.dmp-settings-field > input` 负责满宽、等宽数字与
  `aria-invalid` 红边；边框、背景、focus、placeholder 仍交给宿主 input 自己。`.dmp-settings-input`
  类名不再使用。
- **Switch**：转发 `className`，根节点是
  `<button role="switch" class="_switch_* dmp-settings-switch"><span class="_thumb_*"></span></button>`；
  轨与滑块规则确实落在真实节点上。打开态滑块用 `--zmd-on-primary`：亮色黑轨白块，暗色白轨黑块。
- **上下文**：`div.dmp-context-presets[role=group][aria-label=常用档位]` 里四个
  `button.dmp-context-preset[aria-pressed]` + 一个「自定义」按钮；只有自定义档渲染
  `.dmp-settings-field > input`。选档位写 `contextWindow`，点自定义展开输入框；继承态不预选档位，
  读数写生效值。鼠标从输入框移到档位按钮时用 `onMouseDown` 跳过那次 blur 提交，避免「先提交草稿、
  再写入档位」的双写。
- **关系**：齿轮的 `aria-haspopup` 从 `menu` 改为 `dialog`，面板 `role` 从 `group` 改为
  `dialog`（非模态）；面板用 `aria-label`（`{model} 的模型参数`）。三个可见标签各带 id，
  分别用 `aria-labelledby` 绑定开关组、上下文输入框和推理 radiogroup；错误行 `role="alert"`
  并由输入框 `aria-describedby` 指向。输入框另留一个同文的 `aria-label` 兜底——primitive 是黑盒，
  避免它在某个版本里不透传 `aria-labelledby`。输入类型读数不重复写值，只有额外模态才写完整集合。
- 这一节的结论是**宿主 primitive 的行为事实**，不是本插件的偏好；宿主升级后要重新核对
  Input 是否开始转发 `className`。

## 取舍（明确放弃的东西）

- **放弃「写入位置」可见区块**：原始路径改为页脚范围句的 `title`。代价是它不再一眼可见；
  收益是面板不再用两行技术路径换取一个大多数时候不改变动作的信息。
- **放弃面板底部的长说明**：「输入与窗口写进声明、立即生效、与设置 → 模型页同处；推理是会话级」
  不再整段出现。前两点由「已自定义」标签和即改即存的控件形态承担，第三点由「仅本会话」标签承担。
- **放弃每段的条件说明句**：`已声明：… / 适配器内置目录公布：… / 尚未声明…` 等键退役。
  来源标签是压缩，不是删除：三种来源仍然可读，只是不再写成句子。
- **放弃「恢复默认」的常驻禁用态**：没有可恢复的改动时按钮不存在；用户改了一项后它才出现。
- **上下文读数是友好值、自定义编辑器是精确值**：继承态读数 `262K`、自定义输入框 `262144` 会同时出现。这是刻意的：
  读数负责扫读，编辑器负责写回，不把四舍五入后的文本写进声明；选中的档位标签则是十进制档位本身（256K = 256000）。
- **不放弃的**：只改当前模型的声明、即改即存、推理等级的会话级语义、只读/加载/错误的三种提示、
  中英同键、`dmp-` 类名域、宿主令牌与 0.5px 线。

## 后果

- 面板高度从 668px 降到 **312px**（同一静态 fixture、同内容、300px 宽；上下文继承态 315px；展开自定义输入框 350px；非法值 392px），在 460px 上限内不再滚动；
  长模型名截断、只读提示 +45px，仍在上限内。
- 窗口与推理等级的当前值不再在读数行重复：窗口看选中的档位或自定义输入框、推理看选中的胶囊；只有上下文继承态（输入框为空）由读数补出生效值。
- 只读部署里开关与输入框禁用、推理等级仍可选；页脚不出现无法执行的恢复动作。
- 切换推理等级时面板不再插入 busy 说明句、也不把控件临时置灰：`settings.busy` 文案退役，面板用
  `aria-busy` 标记忙碌，重复点按由 `pickEffort` 的 `busy` 守卫拦下。原先 pending 一来面板正文被顶下
  再弹回、点击的胶囊淡出再回来，就是用户看到的「闪烁」；现在面板高度与颜色在 pending 前后保持不变。
- **如果整页仍在切推理等级时闪**：那是宿主 `sessions.selectModel` 的会话投影更新（`directory.select`
  先置 `selecting`、等远程 `selectModel` 再回 `ready`），不在本插件的渲染范围内；插件只能保证面板
  自己不跳。
- 上下文窗口的两种刻度仍在（继承读数 `262K`、自定义编辑器 `262144`）；档位标签是十进制档位（256K = 256000），二进制容量会落到自定义档。
- 原始写入路径只在悬停页脚范围句时出现；不悬停就看不到。
- **静态验收的缺口**：面板真实宽度、宿主菜单材质的模糊效果、滚动容器与焦点链仍只在真机验；
  本轮只做了真实宿主 token + `src` 样式表的静态 fixture（亮/暗、300/366px、中英、长名、只读、非法值）。

## 备选（未采用）

- **只压缩说明句、保留表单构图**：读数仍然藏在控件里，句子仍然要逐条解析。
- **「写入位置」做成可展开的一行**：省不下高度，且展开后还是同一段技术路径。
- **上下文输入框预填生效值**：失焦就可能把继承值写成声明值，或者把 `262144` 写成 `262K`。
- **推理等级改用原生下拉**：当前值和可选项不能同时看见，反而降低扫读。
- **页首保留「已自定义」总标签**：与两行来源标签重复，且不说明是哪一项。
